# Architecture Review — 2026-11-24

Scope: docs v0.1 (PRODUCT_SPEC, ARCHITECTURE, DATABASE_DESIGN, ROADMAP, DECISIONS, CLAUDE.md).
Reviewer role: senior architect. Result: docs revised to v0.2. Severity: **H** = would cause wrong
verdicts, data corruption or a security hole · **M** = integrity/maintainability problem · **L** = cleanup.

| # | Area | Finding (v0.1) | Sev | Resolution (v0.2) | ADR |
|---|---|---|---|---|---|
| 1 | Asking vs. sold | `market_sales` held completed sales **and** asking prices / delisted ads, separated only by an enum | H | Completed sales in `observed_sales` + ledger view; asking prices only in spans; typed engine inputs | 006 |
| 2 | Variant identity | One listing → one product; `variant_key` on products. Apparel pages carry many sizes, food pages several packs, laptops several configs | H | product → variant → identifiers; listing 1:N offers; category module resolves variant | 014 |
| 3 | Identifiers | `gtin`, `mpn` single columns on products; one variant can have several GTINs | M | `variant_identifiers` with uniqueness + conflict → review | 014 |
| 4 | Price history stats | Observations "on change only" + medians over rows → biased medians; heartbeat rows mixed semantics | H | Price spans with known intervals; time-weighted stats; gaps excluded | 016 |
| 5 | Benchmark mixing | One benchmark mixed new retail, marketplace, private asks, loyalty and flyer prices | H | `listing_kind` + benchmark bases (`RETAIL_NEW`, `USED_ASK` context-only, `FLYER`) | 021 |
| 6 | Two engines | Single `evaluations` table with nullable columns for both engines | M | Two tables, separate enums, import rule engines ↛ each other | 002 |
| 7 | Append-only contradiction | `evaluations` "append-only" but had `is_current` flag; benchmark history + FK + cache | M | Current = latest id; benchmarks are a cache; evaluations snapshot inputs | 017 |
| 8 | Duplicated logic | Effective price / fee math implied in both engines | M | Single `evaluation/costs.py`; engines import it, not each other | 002, 003 |
| 9 | Category leakage | No rule preventing `if category ==` in shared code; categories could import each other; unit-price & size logic unassigned | M | Protocol extended (`resolve_variant`, `comparison_basis`, `benchmark_policy`); architecture test | 012 |
| 10 | Duplicated state | `listings.current_price_huf` duplicated latest observation; `match_method/confidence` duplicated candidate; `cost_basis_huf` duplicated ledger; own SALE copied into `market_sales` | M | Derived from spans / accepted candidate / ledger view | 014, 019 |
| 11 | Ledger | Signed amounts (sign bugs); no multi-unit orders | M | Positive amount + direction + CHECK; `acquisitions`; one item per unit | 019 |
| 12 | Claude CLI / file hand-off | Proposed letting Claude Code (an agent with shell/file tools) read untrusted listing text | **H (security)** | Clipboard/file with paste-back by default; CLI only with `--tools ""`, no MCP, empty temp dir | 011 |
| 13 | Streamlit exposure | Network bind address and usage telemetry not specified | H (security) | Explicit `127.0.0.1`, telemetry off, XSRF on | 020 |
| 14 | Personal data | Private sellers' names/contacts could be stored from classifieds | M | Salted hash only; no contact data; retention | 020 |
| 15 | Concurrency | Task Scheduler run + UI writes could collide | M | Single-writer lock file + WAL | 018 |
| 16 | Product explosion | `created_by RULE` from any listing → duplicate products | M | Auto-create only with identifiers; merge pointer | 015 |
| 17 | VAT | B2B shops show net prices; not modelled | M | `price_is_net`, normalized to gross, unknown → MANUAL_REVIEW | 021 |
| 18 | Ruleset ambiguity | Unclear if rule logic or params live in DB | L | Logic in code (`code_version`), params in `rule_params` | 022 |
| 19 | Unverified tooling claim | "ruff rule bans float(" — not verified | L | Project AST test instead | 007 |
| 20 | Fees uncertainty | Unverified fee profile only "flagged" — conflicted with "uncertain → MANUAL_REVIEW" | M | Unverified fee/tax profile ⇒ review flag ⇒ MANUAL_REVIEW | 005 |
| 21 | External id | Sources without stable ids (manual, flyers) would break unique key | L | `url:<sha1>` / `manual:<uuid>` scheme | — |
| 22 | Hidden costs | None found. FX rate source and notification channel were unspecified | L | MNB official rates or manual; free channels only | 023 |
| 23 | Unneeded deps | `hypothesis` floated; APScheduler considered | L | Removed; stdlib `difflib`, Task Scheduler | 009, 023 |

Not changed (reviewed, kept): modular monolith; SQLite; Alembic; typed per-category attribute tables
(not EAV); MANUAL_REVIEW default; source access policy; phase order.

Residual risks (cannot be designed away):
- Completed-sale data is scarce on free Hungarian sources → resale engine will be conservative for months.
- HTML parsers break on site changes → DEGRADED detection limits the damage but needs user attention.
- Matching quality for apparel/home without identifiers depends on user review effort.
